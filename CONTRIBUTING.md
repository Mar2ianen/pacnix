# Contributing to pacnix

## Лицензия контрибуций

Контрибуции в этот проект принимаются под лицензией:

    MIT OR GPL-3.0-or-later

(SPDX-License-Identifier: MIT OR GPL-3.0-or-later)

Это важно: возможность будущей смены dependency stack и пермиссивного
переиспользования собственного кода зависит от того, что весь вносимый код
доступен под той же двойной лицензией, что и остальной проект.

Отправляя PR, вы соглашаетесь, что ваш вклад распространяется под
`MIT OR GPL-3.0-or-later`.

Каждый новый Rust-файл должен содержать SPDX-заголовок:

```rust
// SPDX-License-Identifier: MIT OR GPL-3.0-or-later
```

## Архитектурные правила (сводка)

- Core не знает про CLI: в `pacnix-core` нет `println!` для UX, чтения stdin
  и интерактивных вопросов. Core возвращает структурированные данные, планы
  и запросы на взаимодействие (`Interaction`).
- Backend отвечает только за свою экосистему; зависимости остаются
  backend-local. Зависимости никогда не удовлетворяются из другой экосистемы.
- Resolver и backend — разные сущности. Resolver отвечает «что имел в виду
  пользователь», backend — «как этим управлять в своей экосистеме».
- SQLite хранит только собственный слой координации (provenance, aliases,
  cross-backend identity) и пересобирается reconciliation'ом из authoritative
  state backend'ов. Удаление `pacnix.db` не должно ломать систему.
- Команды и флаги map'ятся в единый внутренний `Command` enum.

## Как работать

1. Создайте feature branch от `main`.
2. Работайте над одним связанным изменением.
3. Добавляйте тесты вместе с реализацией.
4. Проверьте: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`.
5. Откройте PR с описанием, что меняется и почему.
